# PPTX 制作全流程

## 1．内容和统一设计

在 consumer 前置后，把内容写入 `content.json`：受众、演示场景、整套要回答的问题、逐页职责、准确可见文字、图注、来源和会影响结论的限制。标题表达当前页主题或有证据的发现，避免把“研究 / 执行 / 交付”三个词当成所有题目的叙事。页数包括封面，除非用户另有说明。

每页同时记录标题来自用户逐字指定还是主模型拟定，再记录固定/常改和原生/艺术角色。来源不决定表现形式。固定封面或章节标题可承担艺术焦点，其他页面可用同一字体角色保持协调；不把每页全部金属字或全部粗黑字当作统一设计。主模型拟题仍先满足consumer内容准确性，用户指定标题不因做艺术字而改写。

同一份逐页内容同时记录艺术/原生职责、对象清单与数字白名单（含单位、时间、价格）。母图和提层返回时，包装、贴纸、牌面上的可读小字也逐项核对；不允许把未指定的库存、销量或临时时间当装饰放过。白名单帮助实际看图，不声称脚本能自动读懂所有艺术字。

`design-system.json` 定义画布、色号、字体角色/字号、边距网格、背景语言、导航和版式族。背景可共用，视觉意象按内容变化。版式族例如封面、解释、流程、证据对比、规格表、边界；这些是候选，不强塞给每套稿。

为主标题、二级栏目、当前/非当前导航分别指定已采用的字形锚点，可引用代表页中的对应素材。后续母图、提层或改字时携带该角色的实际参考与必要字形特征，不能只给同色背景就视作继承。不同角色可以分别用刀刻衬线、手写字等；同一角色跨页保持家族关系，尺度和版式仍可随内容变化。

导航以稳定 section_id 关联章节，page.section_id 决定 active 状态。四章就建立四个完整状态，固定坐标和艺术语言。当前章通过尺度、字重、节点/线段等层级突出，其他章弱化但可读，不能仅靠颜色。不要把“艺术导航”缩成常规小字换个字形加下划线。是否可点击是单独需求，默认只做视觉导航。

## 2．完整代表页和推荐编辑架构

准备最能体现真实信息密度的代表内页，封面有独立视觉难点时同时验证封面。先确定完整艺术效果，设计标题、导航、固定标签、正文与图表的关系，再按角色争取编辑能力。原生与原素材确能实现该方向时直接构建并渲染；艺术场景或展示字形主导时，先由图片模型设计完整母图，再拆层，不先搭通用文本框让视觉迁就它。引用同一已选方向，页级改变结构，不让每页重新选择字体和色号。需要生图时使用prompts/pptx-design.txt；预期原生的文字也要在母图中有合适的字形与层级，不能只是普通占位字。

看实际代表页渲染或母图，重点检查阅读顺序、字形、导航层级、准确内容与留白。把视觉方向和推荐编辑职责一次展示：

有指定原图时，在此阶段就用完整原图做一次实际槽位预览，检查照片、标题和正文的比例；预览可暂用完整母图作底，但须明确它不是已分层成品。依据 [主题与尺度判断](visual-production.md#从主题到可判断的完整页面) 修整页关系后，再扩大到其他页。页数与是否包含封面始终来自本次 brief，不沿用示例。

| 内容 | 常见推荐 | 交付后能做什么 |
|---|---|---|
| 大标题、导航、章节标识 | 以完整设计为准；原生真实字形匹配则保留，否则独立艺术文字图片 | 原生可改字；图片可移动/替换 |
| 固定说明、设计标签、艺术强调数字 | 与主视觉同样匹配气质；不能因不是大标题就使用默认字体 | 图片内容变化须从同一文本/数据源局部替换 |
| 常改正文、日期、金额 | 尽量用匹配的原生文字；真实冲突按已定美观/编辑优先级取舍 | 原生可直接输入；图片需整层替换并明确说明 |
| 证据数据图、表格 | 需要改数据时保留真实原生图表/表格；另有视觉取舍则明确边界 | 原生可改数据/单元格；图片不能冒充数据可编辑；均须准确 |
| 大面积连续背景 | 共用真实母版 | 更换背景需要母版/背景设置 |
| 低频编辑的页级宽光效 | 真实版式 | 普通页不易误选，需版式视图修改 |
| 需要移动的主要物体 | 普通页语义图片 | 独立移动；光影是否随物体须说明 |

这张表用于逐角色取舍，不是原生数量或全部图片化配额。未被用户放宽的可输入要求要守住，发生冲突时说明具体角色；已明确允许美观优先的按该选择执行并标明边界，不重复确认。全自动按最小充分编辑职责继续，不逐页逼用户批准。

固定文字同样遵循[文字角色与编辑取舍](native-text-routing.md)。已验证的混合导航可分离装饰与原生字；若原生字形不匹配，则复用同家族的艺术文字素材和状态。正常/活动态均服务整页设计，不把导航做成后贴的系统UI。

## 3．逐页设计，按对象路由执行

代表方向确定后，原生角色复用项目样式源直接构建；确需生图的余页母图与代表页提层/重组交错。使用 [滚动调度](rolling-scheduling.md) 的就绪依赖、有限窗口和逐项消费，不能等代表页组装完成才提交独立图片任务。调用前确定每页的章节状态和准确文字。固定导航复用统一组件与完整状态样式，固定各章槽位，不让活跃文字放大挤动其他槽位。母图错数字/刻度登记为待修；最终原生图表使用真实数值、共同零点和准确轴，不把模型图形当数据真相。

每页只提取有编辑价值的语义对象。背景移除所有独立文字和主体后补全；艺术标题/固定文案/导航保持原形状、大小和材料关系；主体补全必要遮挡。先提取代表页的难对象，做一次真实重组，对照通过后扩大。若调用工具只能返回整页扁图，说明分层还没完成。

每页母图核对后就释放本页语义层任务。提取前说清材质属于物体还是承载纸面；多对象图集要求透明沟槽、阴影不跨槽、无连体台面。区域切分前检查边界 Alpha 和主体完整性；若仍相连，局部重提，不能抬高阈值硬抠除来假装独立。

提示词每次包含低噪、平滑渐变、精确轮廓要求。不要把玻璃质感无差别复制给所有艺术文字。文字输入给模型后仍要目视核对，错字只修责任层。保留背景中烘焙的折射限制，不承诺物理透明。

## 4．紧裁与忠实定位

独立透明素材通常先按原画布生成，以便对齐母图。保存原图后运行 crop_alpha.py，按有效 Alpha 边界裁外围空白，并保留合理软边余量。默认 threshold=1 保留所有非零 Alpha；若少量随机噪点撑大边框，优先清理该素材，或在实际看图依据下提高阈值并记录丢弃量。不要通过高阈值把阴影硬切掉。

源图尺寸 W×H，原目标 [x,y,w,h]，裁剪框 [cx,cy,cw,ch]：新目标为 [x+cx·w/W, y+cy·h/H, cw·w/W, ch·h/H]。脚本写 ledger，禁止裁完后仍用原全画布尺寸放图。

紧裁后若改用新的排版槽位，须区分素材框与contain容器：宽容器会把较窄图片居中，不能仅凭容器左坐标认定文字左缘对齐。需要精确对齐时按实际裁后长宽比设置图片框，或显式补偿留白；以实际导出PNG核对，不拉伸字形。

透明 PNG 内部孔洞仍处在矩形对象边界中。若宽光效挡住常编辑文字，可拆为独立对象，或经编辑职责约定放版式；不要移到背景后仍宣称能在普通页点选。fixed_layout 图片处在普通页对象之后，不能承载必须盖住正文的前景效果。

## 5．原生内容和真实组装

按 [deck 契约](deck-contract.md) 把设计坐标、紧裁素材、原生文字/图表/表格写进 deck.json，元素数组即普通页绘制顺序。坐标来自已定完整构图、参考模板或母图，不新造默认布局。可选text_styles与style_role在编译时解析；纯色背景可直接写theme.background而省略background图片，见[样式源与单位](native-style-tokens.md)。

原生文字核对真实字形、字重、字距、斜体、行距与基线，不能只查fontFamily字段。一次代表样本暴露回退且无可靠修正依据时，把已获准的责任角色换成独立艺术文字图片，不为“全原生”牺牲设计；金额、日期等已匹配的角色仍保留原生。原生图表与艺术数字绑定同一data.json；构建前检查绑定值和资产哈希，过期时输出局部替换任务并停止发布该版本。

执行 assemble_pptx.mjs，输出当前 build 的 final.pptx、实际回读 PNG、结构验证和对象检查记录。构建器写一个真实共享母版背景，并把 fixed_layout 图片置入各页真实版式；普通页的语义图片/文字/图表/表格保持独立。构建输出新版本，不覆盖旧稿。命令与必要环境见 [PPTX 工具](pptx-tools.md)。

代表页一次真实重组后，各页素材齐全就准备坐标和轻量预览。先处理越界、硬截断和比例问题，再汇合做正式全套构建；不要一层、一处坐标小修都跑整套 finalizer。最终实际回读和编辑验证仍须完成。

代表重组至少回答本项目真正需要的编辑动作：哪一个语义图片可独立移动，哪一处正文或数据可以原生修改，隐藏主体后背景是否完整。把这些动作对应到实际对象名和源资源；不以整页位图加几个透明文本框冒充设计已还原。

## 6．实际审阅和编辑验证

负责交付判断的主模型亲自逐页打开实际PPTX回读PNG，再看全套总览；不能只接受子代理的通过报告。拿代表页母图与重组同尺寸对照，检查标题、导航、固定说明和正文的字形气质、光影、主体比例与留白是否保留，数字与图形是否准确。母图漂亮不是PPTX成品通过，字体名、层数和结构检查也不能代替此判断。不设像素对应率。

代表封面好看不代表正文页已经延续设计。第一版全套可见时，做一次轻量缩略图联看：遮住品牌名，信息页是否仍有该主题的视觉身份；标题、正文、数据与下一步之间是否有清楚的阅读节奏；是否只有封面有设计、后面退成同款粗黑标题和通用分栏。可以并列现有逐页预览，不为总览新增生图或审批。发现问题后优先复用已合格的字体角色、原图与一组装饰，针对责任页重排；不要求每页独立背景，也不把某次纸页、面包或夜读意象变成通用模板。原生可编辑与整套审美分别判断。

在总览中按同一文字角色横向核对，而不只看配色相近。若某页主标题或当前导航偏离已选字形，只修该角色的素材与放置；保留已合格的二级文字、正文和背景，不为统一而抹掉角色层级或重生全部页面。

实物场景还要核对 [承托、接触阴影与透视](visual-production.md#先保住场景中的空间关系)，共享母版不能成为删掉本页必要空间关系的理由。底部的结论或决策句属于正文，须留足完整行和下方空间，不能与页码、页边挤在同一视觉区域；在实际导出尺寸中判断，不以文本框未越界替代可读性。

对测试副本移动一个主体或标题，改字、换成实际可能出现的长文、改字号；有图片则换一张同职责素材，图表/表格则改真实数据/单元格，另存后再开。导航要切换后再切回，核对所有正常/活动样式、标签框与活动装饰，不能只检查新活动字。长文超预算时按已批准设计调整或报告边界，不暗中缩字、扩框或挤走邻居。记录实际对象和结果；正式PPTX保留完整图表工作簿，诊断重导出副本不能冒充正式成品。当前工具往返可能丢失依赖，详见pptx-limitations。

也从实际导出的PPTX读取讲者备注：逐句判断它是否帮助听众或讲者解释当前内容。保留来源、必要数据口径和限制；把模型选择、组装方法、核验自评及无关的旧稿取舍移到工程记录或编辑说明。修复后重新读取备注，并检查页面正文没有一起丢失。判断阅读用途，不靠“模型”等词的机械过滤来删真实业务内容。

有目标应用且获授权时，在实际 PowerPoint/Google Slides 选择、移动、改数据、保存再开。没有实机只能报告 OOXML 对象边界、工具回读编辑及渲染观察，不写“点击验证通过”。技术验收与用户审美认可分别记录。

## 7．局部修复、中断与交付

定位问题只改目标框；艺术标题不好，回到那一页完整设计判断，不连续换几张孤立字贴。导航体系不好，先改代表信息页和系统，再扩全套。每个失败尝试保留原因和真实调用记录，同一责任层不做没有新依据的无限重试。

### 已批准方案中的局部改字或改价

先定位文字/数据的唯一来源及所有受影响展示，包括同一金额的备注；确认此次请求没有改变范围、税费或服务条件。本流程新建的可重建工程，另存内容或数据版本与deck配置，只改对应原生对象，复用未受影响的母图、语义素材、母版和版式。文字本身为原生且不需要改变艺术资产时，不调用图片模型。若它是已绑定的艺术图片文字，仍走局部图片替换与过期标签检查，不暗中降为普通字。

验证改动页的实际文件，同时核对未授权改动的范围：内容、对象位置/样式、指定媒体身份及图表/工作簿数据。重建器可能重排ZIP元数据或重新分配关系ID，整个PPTX文件哈希不同不等于版式被改坏；反过来，资源相同也不证明正确放置。按当前变化选择结构比较与实际渲染对照，不新增统一像素相似率。一次改价实测的边界见[回杯站商业实测](commercial-trial.md)。

这条重建路线适用于本流程自己的源工程。用户只给已有PPTX而没有本工程时，仍按当前Presentations的实际导入/编辑路线保护原对象，先识别往返可能丢失的功能，不为改一处价格默认重做整套。

若实际导入重导出丢失了用户要求保留的原图表依赖，见[原依赖保全案例](roundtrip-preservation-case.md)。它只在对应关系和原字节可核实时恢复丢失依赖，不授权另起低级内容作者、不弱化finalizer；无法可靠保全就报告准确阻断。

### 中断恢复与交付

用 resume.json 保存本次 format=pptx、当前 deck、母图、采用素材、各页已完成项、build、待办和等待谁。切换版本前备份 JSON；独立生成可并行，登记/修改 deck/data/bindings 串行。续做重查文件存在和来源，不能把上次准备的 job 当已调用。

交付 PPTX、单独 PNG/PDF 预览和简短编辑说明。源包包含当前内容/数据、deck、用到的紧裁素材、生成来源和可重建代码；原始母图可单独存，避免大包阻塞成品。说明艺术文字改法、原生数据与艺术数字的同步、母版/版式入口、字体及未测应用。内容可读性仍要按 consumer 审阅，用户认可视觉不等于每句文案已最佳。

需要交给新 AI 时，在 [START_HERE](../resources/handover.md) 写出本项目的实际 assemble 命令、plan 参数、当前 data/content 文件和最新构建。把依赖的素材及相对引用一起打包，在另一解压位置确认引用可用；已有完整素材时重建不调用图片模型。进一步改价、日期或数据要生成新版本并核对未改范围，不用上一版整包哈希相同作为要求。
