# 原生样式源、单位与实测边界

为当前作品定义标题、正文、注释、数据、正常/活动导航等实际角色。角色名、字体、颜色、字号和状态数量来自主题与内容；不要把研究样例的75/40pt、两字标签预算或纸纹装饰变成所有项目的默认模板。

## 可执行入口

`deck.json`可选`text_styles`保存当前JS后端完整样式；text对象以`style_role`引用，编译输出仍是既有`style`。示例字段如下，数值只展示契约，不是一套通用视觉设计：

```json
{
  "text_styles": {
    "section.normal": {
      "typeface": "Noto Sans CJK SC", "fontSize": 32,
      "bold": true, "italic": false, "color": "#244B58",
      "alignment": "left", "verticalAlignment": "middle",
      "autoFit": "none", "wrap": "none",
      "insets": {"left": 0, "right": 0, "top": 0, "bottom": 0}
    }
  },
  "slides": [{
    "id": "S01", "elements": [{
      "id": "section-label", "kind": "text", "text": "项目范围",
      "box": [80, 620, 360, 60], "style_role": "section.normal",
      "style": {"fontSize": 36}
    }]
  }]
}
```

这段是deck片段。可运行的完整合成样例见`examples/pptx-native-roles.json`，按[pptx-tools](pptx-tools.md)用现有`assemble_pptx.mjs`构建；无需生图。项目仍须验证实际字体与视觉，示例不提供字体文件。

合成顺序为角色完整style，再以对象style覆盖同名顶级字段。嵌套对象如insets整体替换，不能只提供一个方向又期待隐式保留其他方向。编译在副本中执行，保留原输入；未知角色、非对象角色/覆盖值报告页ID、对象ID与角色。未使用style_role的旧对象保持原协议。角色引用不自动改变文字内容、框或字号，不会启用隐藏缩字。

## 单位与后端适配

本入口的box和数字fontSize是96DPI的CSS px：`px = pt × 96 / 72`，PPTX几何`EMU = px × 9525`。不要把研究Python bridge的font_size、vertical_alignment等字段直接放进JS style。中英混排、基线、字距、段距、渐变等必须先查当前API；有格式节点不等于当前API能写或往返能保留。

普通字符串及字符串段落数组沿用先写text、再一次赋完整style的顺序。结构化run则先赋角色/对象的整体默认style，再写带局部textStyle的text；不能在末尾再次赋整体字体/字号/填充，否则会覆盖run的显式值。`bold:false`也是真实覆盖，不能用真假判断丢掉它。

结构化段落会替换先前的段落记录，故组装器在输入副本中给未指定行距的段落补默认`style.lineSpacing`。当前JS字段及单位如下：

- 整体`style.lineSpacing:1.25`为倍率，生成`a:spcPct=125000`
- 段落`paragraphStyle.lineSpacingPercent:180000`为1.8倍；或`lineSpacingPoints:4800`为固定48pt。两者互斥，显式段落值优先于整体默认
- 段落顶级`spaceBefore`、`spaceAfter`为百分之一pt，例如600、800分别为6pt、8pt，与行距分开
- run的`textStyle.fontSize`用`"32pt"`或`"42px"`单位字符串，勿与整体数字fontSize混用

`paragraphStyle.lineSpacing:1.8`不是已验证的局部行距字段：本次API接收该未知记录却未写出行距，不能把不报错当支持。其他未列属性仍须查当前API并验证，不把本修复当成完整段落排版引擎。实际多行回归输入见`examples/pptx-native-typography.json`：混合中文/英文/数字与不同run字体、字号、颜色，另含局部倍率、固定pt和默认继承。它是功能样例，不是商业视觉模板。

样式源与能力记录分开：`text_styles`可复用参数，能力证据另按`backend/version或指纹 + renderer/version + font文件hash + recipe版本 + role`登记。改变这些条件后重新验证相关能力。style引用不会使未经实测的属性自动成为已支持属性，也不是PowerPoint主题的双向绑定。

## 固定槽位与完整状态

用稳定section_id决定本页当前章，为每个标签保留固定ID和框。每次状态改变从唯一源重建所有正常/活动样式，只移动需要移动的活动装饰；不沿上次状态只改一个color。重建器新建原生对象，因此不会继承旧活动对象的残留效果。

编辑导入对象时则必须额外检查：整体style赋值不应被假定能清除所有未提及属性。原对象带渐变、描边、阴影或run格式时，按当前API明确重设/清除并实测；不能把纯色研究例的通过扩展成高级效果清除保证。内容、整体样式、分段样式按固定顺序设置，整体样式之后的run样式必须重新应用。需要清除而当前接口无可靠路径时，从原样式源重建该组件或报告该效果的阻断，不擅自改全部页面。

当前JS对研究02的状态切换实测：同时设置目标纯色`color`和`fill`，并显式`outline:{fill:"none",width:0}`，菜单激活后再切回体验，两次保存重开均清除了旧白色字形填充及描边。四个框不变，原图片字节和对象身份保留，活动纸签按新状态移动。这只验证该纯色/描边组件的重置；阴影、纹理、形变的清除仍须各自证明，不能只删除style键就认为清除了。

切换后再切回，保存重开，逐一核对标签文本、字体/颜色/字号、四周净空、旧活动态残影与活动装饰坐标。清空可编辑文字后看装饰是否仍带旧字。视觉导航不自动包含点击跳转；链接需独立实现并在实际放映模式点击验证。

## 长文与字体

预检实际字体文件的家族/字重、字符覆盖和许可，再用代表角色真实导出验证。cmap和advance测量只能排除明显缺字或超宽，不等同PPT排版引擎；设置了字体名字也不等于实际渲染采用该文件。

用本项目实际可能出现的长标题、混排、数字与字号变化测试。先守住准确字面、固定邻居和已批准设计；在允许范围内换行、调宽或调字号，超出范围再问必要决定。每个角色的最小字号和长度预算来自当前设计，不采用统一二字上限。已承诺可输入的文字不能偷偷改为图片来掩盖溢出；允许美观优先时，真实字形小样失败且没有可靠修正依据，就记录差异并转独立艺术文字层，不反复盲换字体名。图片文字仍保留准确文本源和替换说明。

## 证据状态

分别保存written、imported、rendered、edited、saved_reopened、visual_pass、target_app_tested与实际文件/日志；未知为NOT_RUN，已观察失真为FAIL。测试多个属性不等于完成多轮验收。每轮复查须绑定精确源码版本、风险范围、实际输入/输出、观察与修复，新改动后重测受影响范围。

基础文字通过不意味着高级属性全部通过。渐变、描边、阴影、WordArt、字距、基线、中英文混排与目标应用各有自己的证据。研究包的Python bridge/LibreOffice记录是相关先验；当前JS和最终PowerPoint/WPS仍须分别实测。目标软件不可达时保留NOT_RUN/BLOCKED，不能把工具渲染成功改称跨软件通过。

2026-10-01的当前JS实测基线为`@oai/artifact-tool 2.8.59`，供应运行时包`26.903.11726`。它与用户研究包的旧Python bridge是不同实现：

| 范围 | 已观察结果 | 仍不能推断 |
|---|---|---|
| 新建文字渐变、描边及两行混排 | finalizer、重开、PNG通过；局部DejaVu Serif、32/28pt、颜色、bold=false、斜体保留；整体对齐和内边距保留 | 任意字体、字符或目标应用都相同 |
| 多行段落间距 | 局部180000倍率、4800固定pt、默认125000及段前/后分别保留；实际多行渲染有相应间距 | 只凭单行或字段存在验收行距 |
| 旧字符串/字符串段落数组 | 未改页实际PNG与修复前逐字节相同 | 整个PPTX ZIP字节相同；导出会重建内部标识 |
| 研究03导入导出 | 被测gradFill、描边、run阴影、纹理blipFill及spc=300保留 | 纹理精细视觉或所有字距行为通过；kern=0丢失 |

按实际任务选择允许且可用的后端；这些记录界定一次实现的证据，不限制其他宿主使用经实测的原生能力。

## 按目标渲染器选择配方

同一份三页合成稿经本次供应soffice headless入口另行渲染与重保存：`gradient-title`在首次PDF已变成单色，另存PPTX后该对象的2个gradFill节点变为0。它同时有渲染失真和保存丢失，不能只说截图颜色不同。供应入口与版本的准确边界见[媒体预检记录](media-preflight.md#已观察的失败样例)，不是Windows PowerPoint结论。

本次正文、DejaVu Serif混排、两种局部行距及默认继承仍可读；字体度量和行间位置与JS不同，固定48pt另存为47.99pt。三页导入及重开渲染均未观察到字形越出授权框、内容遮挡或缺字。要求是信息与布局可用，不要求不同后端像素完全相同。

需要该soffice入口一致性时，已有实测的替代是原生纯色标题：从已定角色保留字体、字号、框和粗体，把`color`与`fill`同时设为设计色，并以`outline:{fill:"none",width:0}`明确取消描边。合成稿以`#153A70`实测JS写出、该入口渲染、保存重开均保持纯色和可编辑文字；此颜色只是测试值。

这项替代会改变已批准的渐变视觉，只在用户允许的范围或确认取舍后采用。若渐变/材质是不可牺牲的角色特征，可经批准保留该角色为独立艺术图片，再核原图字节、编辑边界和目标渲染；本批未将这种替代普遍批准，也不因此栅格化正文或全页。目标PowerPoint/WPS未知时仍记NOT_RUN，不用soffice的失败推断格式本身不支持渐变。
