# 说明可用性走查与验证边界

以下为 1.1.0 发布时的历史记录，保留原结论。1.2.0 已基于其后真实独立海报试跑修订；当前结果与限制见 [release-validation](release-validation.md)，不可将下文“未做独立试用”误读成后来没有发生过试跑。

日期：2026-09-30；对象：workflow 1.1.0 的实际文件。

## 方法与限制

尝试安排无历史上下文的独立读者，但当时无法启动额外评审，因此本次采用**作者进行的文件独立程序走查**。这不是第二位 AI 的独立通过结论，也不是用户实际试用结果。

走查时只用包内入口、引用、示例和脚本回答下面的生产问题；同时用真实旧素材测试新项目桥接，另行区分“知道下一步怎么做”“程序已运行”“模型生图已验证”三件事。没有新图片模型调用，没有把假想香水海报说成已完成。

## 场景二：没有参考图，需要两个方向，用户只想确认母图

entry=candidate_gallery、interaction.mode=master_only。先建包含全部文字的计划，master 任务生成完整候选 C01/C02。gallery 负责编号，不把同方向小改伪装成多个方向；用户选定后记录具体母图，后续按既定要求继续，不重新增加逐层确认。

新设计任务的完整 copy 输出、无参考时 request.reference_file=null 已测试。真正生成两个新候选没有执行；因此不能报告“新候选生图通过”。这条路径与已有图路径都在主入口明确，而不是暗藏在旧实例中。

## 场景三：一层黑底失败，第二天继续

失败图记录到 rejected，原因与实际来源保存，已有可用层继续存在。resume_note 写缺哪层、下一操作、最新构建；下一位执行者先 status/receipts。查真实透明参数/引用后作一次有变化的尝试；只偏位则调整坐标。修坏可 restore 已知快照，原图片不删。

已测试 rejected 不替换原指针、快照恢复、恢复后源图片仍在、缺引用不产生伪任务、wrong_job_task 不把错误结果登记到别层。没有“每次继续都重新生成全图”的操作要求。

## 功能验证与边界

- Node 的 23 项包装测试通过；Python 的 25 项项目/验证/真实素材流水线测试通过
- 新建项目 → 导入真实历史母图/素材 → 编译 → 输出真实 PSD → 独立解析 → 源包：实际执行，3 组/11 叶层/8 native type
- 候选画廊、实际 PSD 图层导出、本地 HTML 生成、移动副本、诊断包：实际执行或自动测试覆盖
- 原浏览器审阅页面资源来自用户的 LayerForge 包，未重做 UI；新适配器数据与导出文件已测试。当前环境的浏览器拒绝 file URL，独立浏览器进程也受环境限制，因此**未验证浏览器内点击/重置和响应式截图**，不冒称已验证交互
- 未做真实 Photoshop 打开/修改/保存；未新生图证明提示词成功率；未做独立新 AI 的端到端生图试用

这些限制不会被“单测通过”掩盖。后续真实使用若发现执行断点，应按具体缺口改对应步骤/工具，不再靠堆门禁或整体压缩说明处理。
