# 视觉生产与判断

## 一张计划足够，不创建新的审批系统

使用 plan.json 记录目标尺寸、实际设计基准路径、完整文案、每层拥有的内容、需要补全的遮挡、文字类型和当前待修问题。`examples/production-plan.json` 仅是补充思路，不必复制成第二份状态。保留母版/方向与图层架构两个有价值的确认节点，可合并一次展示；全自动授权可自主记录继续。无需哈希签票、状态迁移或逐层机器批准。见 [交互方法](interaction-and-layers.md)。

已有图：先辨认完整文案与结构，再拆层。用户说“模板图”通常是在指希望拆开的成图；不要因此自动去套用商业模板。新创作：先定主题、主视觉、字号关系和留白；整体候选必须包含最终文字方案。可用无字艺术底图作为中间素材，但不能到最后才临时塞标题。

## 大胆的方向与合理重构

母版阶段敢于在一个主题签名上做强选择：不寻常的尺度、明确的材料对比、非对称张力或独特展示字形。选择从主题本身推导，不因“更大胆”就堆多种装饰。其余文字和信息保持安静、可读、有秩序。用户已有品牌或明确方向优先，不擅自改成执行者喜好。

选稿后，拆层重构优先守住：主视觉身份与数量、字形轮廓和准确文案、版式主次、重要遮挡、实际编辑用途。次要纹理、细小反光、颗粒与非关键边缘允许自然变化。修正改善作品的地方，不为了“更像”把好作品反复生坏；到达用途就交付，不以“约 95%”编造精度成绩。

## 从主题到可判断的完整页面

先指出页面要让读者看懂的一个对象或关系，再从材料里选它的物体、环境、动作和文字。顺序可以用先后位置，包含可以用内部与外部，协作可以用双方汇合的位置；图像也可以只负责展示或营造体验，按本页用途选择。统一对象身份、字体与色彩关系，允许不同页改变场景和构图。

例如食品提案中的真实食物、包装与取餐顺序可以共同构成视觉语言；不是把麦穗、撕纸和橙色复制给别的行业。试用提案若只把“7天”放大，仍需读者自己拼出过程；一个点位配有起止的时间跨度，可以把送装、连续试用和回收组织起来，正文保留双方条件与服务边界。材料不足以支持实物场景时使用明确标注的示意，不补造设备外观或效果。

设计提示词写清各元素为何出现、谁是主体、读者先看什么，以及常改信息将留在哪里。先写关系与视觉作用，再按选定方向给必要的位置约束，避免在关系未定前锁成通用分栏。不要求每个主题都同时有物体、包装和流程。

对母图作下面几项实际判断，发现问题才改，不把它们做成逐项审批或固定模板：

- 主题关系：去掉品牌名以后，主要图形是否仍能说明这个主题？若只剩通用金属字、光环或抽象飘带，回到物体、环境或动作重新组织整页；装饰本身合理时不机械禁用
- 信息重心：真正的产品、人物、场地、数据或关键条件是否足够突出？标题放大、立体化和厚边框可能反而挤压它们。按实际阅读顺序调整尺度和留白，不套统一标题占比
- 媒体实插：原图须完整保留时，在确认母图前用独立原图对象放进真实槽位，看等比显示后的面积、背景和边缘关系。槽位中空时的漂亮不能代表实插后的效果；不要通过重绘、拉伸或裁掉原图解决不匹配
- 材质节制：先看缩览的主体和文字，再看近处纹理。噪点、厚投影或浮雕干扰辨识时，降低责任层的强度，保留主题需要的材料特征；不要把全部对象都换成同一种玻璃、金属或纸纹

母图的构图有问题，就把准确文案、实际媒体尺寸和这一个问题交给图片模型修完整页；已经成立的构图只需移动、缩放或改原生文字，则修改配置并实际重组。错误艺术字只修该字层。依据问题选择调用粒度，不用连续生成孤立标题来补救主体比例，也不因正文可编辑就退回普通三栏版式。

母图和实插预览只用于选定方向。随后按编辑动作拆分背景、主题主体、艺术字与必要效果，重建原生文字和数据，再看真实 PSD/PPTX。可移动的艺术字并不等于可逐字输入；真实原图独立插入也不证明背景和其他文字已分层。

## 图层拆分的尺度

### 先保住场景中的空间关系

母图中的实物原本放在哪里，要在拆层时明确归属：主体本身、承托它的桌面/台座/地面、贴近底部的接触阴影，以及环境光影是否分别属于背景或主体。桌沿、水平面和透视方向可能承担主体“放得住”的依据，不能在清理背景时一起删掉，只留下漂亮透明抠图。接触阴影可随主体保留，也可按编辑目标独立；不是强制每件物体再增加一层。

完整背景要清除不应残留的主体和文字，但保留仍服务构图的承托面与环境。多页可以共享背景语言和母版，不等于每一页只能使用同一张无场景背景。某页需要特有的台面或空间结构时，保留为该页背景/版式语义素材，不能为了共用一张底图让实物变成悬空。

再沿承托关系往外看一层：物体放在台座上，不代表台座已经落地。母图靠连续桌面延伸出页边来建立空间时，提层可保留“主体＋接触阴影＋连续前景台面”的场景单元，而不是强迫它变成四周透明的小岛；母图确实需要孤立物体时才做孤立抠图。说明这个单元能整体移动、哪些边界原本与画布相接。组装后重新检查它与标题的实际遮挡，必要时小幅调整位置或尺度；不能用恢复承托为理由盖掉一个字。

代表页重组后把母图与实际输出并排看：物体底部是否仍接触承托面，投影方向和透视是否相容，前后关系与尺度有没有改变。再隐藏/移动该物体，检查残影和背景完整性。透明边缘正确、对象可移动，只证明提层的一部分；它们不能代替这次整页空间判断。母图本来就是经过选择的悬浮或图形化构图时，保留那个设计，不凭空添加地面。

一层对应一个有用的编辑动作。例如：换背景、移动产品、关掉前景花瓣、调节光效、改说明文字。产品上的正常纹理属于产品；需要单独调强度的光晕才另列效果层。文字角色应由一个明确层拥有，避免背景上残留同一份文字后又叠第二份。

来自 LayerForge 的实用分类：background / object / effects / glass / shadow / typography / decoration。分类帮助沟通，不要求七类全部出现。一般先准备少量关键层，独立性不足再拆，不以层数多为成就。

背景层应是干净、连续的完整背景。主体被遮挡的部分可以生成补全，以便移动时不露洞；不必为永远不会显露的复杂细节无限补画。若用户要求产品结构绝对可信而输入没有该视角，应索取必要图片或说明重建局限。

## 如何定位：视觉主导，数值辅助

1. 观察母图中的目标包围框、中心点、倾角和遮挡边界
2. 检查生成素材相同位置；相近则直接组装
3. 偏了就用配置的 crop / destination 做平移、去外侧空白、缩放。统一缩放优先；明显拉伸会改变字体/产品比例，不应为凑框强行使用
4. 叠回整体，重新看对象之间的关系。正确的包围框不保证轮廓、视角或遮挡正确

`probe_assets.py` 给出多个 Alpha 阈值下的包围框，仅供参考，`alpha_bbox_comparison` 明示为严格大于（Alpha > 键值）；不要与 `crop_alpha.py` 的大于等于阈值混用。柔光应观察低阈值范围，实体可参考较高阈值；不要把测量阈值拿去删除透明度。不得用一套全局边缘阈值判定所有材质。

### 玻璃：独立抠出不等于背景自适应

probe 的 alpha_distribution 记录 Alpha=0、1–229、230–255、255 和所有非零像素的数量，以及近不透明像素占非零像素的比例。外侧透明而主体内部几乎不透明的图仍是可移动的 cutout，不能只凭最小 Alpha=0 宣称玻璃透射已恢复。阈值区间只是描述，没有自动合格比例。

实际叠回原背景，并按编辑用途检查浅/深或不同底色上的透视：硬边是否染底色、玻璃内部是否跟随新底色变化、移动后是否携带旧背景纹理。若内折射已烘焙，说明“独立移动素材，内部折射仍包含原背景影响”；不要承诺物理正确、任意换背景自适应。用户原本就要求频繁换背景时，这是架构能力取舍，应在大量生产前说明，必要时询问。

不要统一降低整层 opacity 伪造真实玻璃，实体标签与高光也会被一起削弱。也不为弱透明尾部清理方便而阈值化删除 Alpha。

允许和原图有轻微纹理、细小反光、非关键装饰误差。应修复明显偏位、错误数量、主体变形、重复文字、产品边缘污染和错字。这里没有一个对所有海报成立的 95% 数学阈值，也不要求 100% 像素还原。

## 视觉检查一次抓重点

- 整图缩览：主题、主次、颜色、留白和大致布局是否保持
- 关键局部放大：主体轮廓、字体、透明边缘、遮挡是否合理
- 文案核对：逐项对照准确文本；OCR 可辅助，不能替代对难字/数字的实际观察
- 隐藏主物体：是否露出干净背景，是否有重复物体残影
- 隐藏文字：是否还有不该残留的文字；原生文字类型与声明是否一致

每次审阅用新版本目录，按 technical report 的 layer/file 映射确认隐藏的是哪个叶层或整组。图像展示与文件看起来不一致时，先复核实际路径、哈希和版本，再诊断；未复现的显示异常不应当作 PSD 程序缺陷。必要时附单图，避免把多图顺序当证据。

不要求每层生成一套正式审查报告。技术验证可以自动化，但艺术判断必须来自真正看过图的人或具有图像理解能力的智能体。记录“已看/未看”和剩余问题，比计算漂亮的假分数更有用。

## 有限修复

先诊断是哪类问题。尺寸/偏位用布局修正；局部错字或串层用针对性的图像编辑；工具未收到参考图则修调用。模型输出没真实透明时检查工具的透明参数，再考虑授权的背景移除工具。保留成功部分，不为一处细节重做整张。

默认一个责任问题最多两次有变化的修复；这是避免盲试的工作预算，不是永远禁止第三次的惩罚。若用户希望继续精修，先说明当前收益和需要的额外尝试。达到使用目的就收尾；达不到关键要求就如实交付受限版本或提出必要问题，不能借容错放弃实质内容。

本版本不接入 LayerForge 的 A/B/C 门禁、票据系统、强制 identity 和 SSIM/边缘分数审批。源素材保留、单一视觉任务、语义所有权、软 Alpha、局部修复和真实交付证据仍然保留。
