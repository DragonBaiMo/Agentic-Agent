# PPTX 文字：逐对象辨认造型，再选择载体

先服从用户已定的文字表现与编辑职责。美观第一不等于普通文字图片化。能用合适字体配合字号、字重、字色、字距和行距实现的普通文字，必须保留原生可改字；宋体、楷体、放大、加粗或固定文案本身都不是艺术图依据。真正需要特殊笔触、非标准字形、大小穿插、形变、纹理或场景融合的对象，再比较原生艺术字与独立艺术图片的实际能力。艺术性看形态，不由“标题”“导航”或“固定/常改”标签决定。

## 四项判断作用在每个文字对象

| 判断 | 要回答的问题 | 对载体的影响 |
|---|---|---|
| 实际造型 | 是标准字形与常规排版，还是独特笔风、异形轮廓、穿插、材质或场景融合？ | 普通造型用原生文字；艺术特征只说明需要艺术实现，不自动等于图片 |
| 原生实现能力 | 当前字体、常规格式或已验证艺术字能力能否表达这个效果？ | 能做到就保留原生；字体声明正确仍要看真实字形。不能把加载错误当成字形天然不可原生 |
| 业务用途 | 它在说明费用、条件、栏目、正文或数据，还是承担独特视觉签名？ | 费用标签、条款等即使固定也应原生；视觉签名可按真实造型选择艺术层 |
| 编辑频率 | 后续是否常改字、金额、日期、状态或长度？ | 决定编辑预算和复验重点，不单独决定图片化 |

记录这四项及最终载体、可改范围和实际证据。无需为每个字做一张审批表。一个区块可同时含艺术主标题图片、装饰图片与原生栏目/正文，不能因区块有艺术标题就整体烘焙为图片。用户明确指定必须保真的原图、Logo或图片对象仍按原件约束处理，不为原生化篡改原资产。

两页夜读案例中，“七日体验的费用与约定”有大小穿插、特殊笔势和金色材质，保留艺术图片；“每店费用·人民币”“含税体验费”“可退押金”“开始前合计”、右侧栏目及条款只有常规宋体排版，改为原生文字。整页美感与原蓝灯保留，并不需要让这些普通字继续成为图片。这是判断示例，不是今后所有标题或费用页的固定模板。

## 标题的来源与表现是两个判断

用户逐字指定标题时保留准确字面；视觉重做不自动授权改标题。主模型获准拟题时，先根据实际受众、页面职责和材料确定题意，再选择平实主题名或有证据的结论。不要为了适配漂亮字形添加无依据的口号。旧PPT仅作内容参考且已授权重构时，其标题也可重拟；不能把所有材料中的标题都当成用户逐字锁定。

随后按上述四项判断固定/常改及native/art。用户指定的标题可以是普通原生字，也可以是确有特殊造型的艺术字；主模型拟定标题同理。它们并非“用户标题原生、AI标题图片”，也不是“标题一律图片、正文一律无艺术性”。记录方式见deck契约中的title_contracts，不再重复询问已授权事项。

## 执行顺序：判断、混合、校字形、验证编辑

1. 先在完整构图中逐项辨认真实造型、用途和编辑要求；不要从默认文本框布局倒推作品，也不把固定文字预先归为图片
2. 普通文字核对合适字体、字重、字宽、字号、字距、行距、斜体和基线，用真实代表样本校准。确有特殊造型的艺术字再核当前后端能力，选择原生艺术字或语义艺术图片
3. 真实渲染的气质、层级、轮廓和阅读关系达标，就复用该原生样式。字体名、安装记录或XML字段正确不能替代看图
4. 普通字出现回退时查实际字体文件/集合字面、加载与渲染链，见[字体核验](font-calibration.md#pptx字体声明与实际字形)。不反复盲换名字，不用粗黑体或图片掩盖问题。仍无法解决就说明普通文字原生效果未达要求；“美观优先”不是自动放弃可改字的授权
5. 文字和装饰可分离时采用混合组件。统一导航槽位与状态；普通导航文字保持原生，只有确有特殊字形的部分采用经选择的艺术实现，不为每页重新生成整条导航

将判断写进当前内容/对象清单，例如“对象费率标签；普通宋体加粗；当前原生字体和样式可实现；说明收费口径；偶尔改；原生；已看回读字形”。艺术对象则写具体损失，如“字缘不规则墨迹与烟雾相融，当前接口只能保留字面，选独立艺术图”。这只是交接记录，不是新增deck字段或自动艺术分类器。

图片模型收到的是该对象需要呈现的准确文字、字形特征和实际参考；不要只说“标题艺术化”。提干净背景/装饰时明确排除将重建的普通文字。组装后隐藏或清空原生对象，确认原位置没有烘焙旧字；不能在图片字上叠透明文本框虚报可编辑。

最后用真实文件的诊断副本逐个编辑本次新增或改造的原生文字，覆盖其实际长度、混排和字号变化；导出、重开并逐项读取目标文字，再打开受影响页面检查缺字、回退、换行、裁切和邻接留白。核对未改艺术、指定原图、金额事实和其他对象；正式稿保留准确内容，不交付测试文案。重复样式可复用字体小样，但不能因此漏掉某个本应原生的对象。方法见[pptx-tools](pptx-tools.md)的真实编辑入口；目标应用未测单列NOT_RUN。

## 用不同情境检验判断，而非记住角色名单

| 看到的对象 | 应怎样选择 | 容易犯的错 |
|---|---|---|
| “费用说明”只是宋体放大加粗，担任页面主标题 | 原生；调字族、字号、字重和间距 | 因为叫标题就整块出图 |
| “含税体验费”是固定栏目，使用普通楷体 | 原生；先验证合法可用的楷体实际加载 | 因为固定或字体有古典气质就认作艺术图 |
| 一句正文绕着烟雾延伸，字缘有逐字不规则飞白与遮挡 | 按实际造型核原生能力；无法保留这些特征时独立艺术图，保留准确文字与替换入口 | 因为是正文就强行普通文本化，丢掉用户要的效果 |
| 标题只有多个字号、两种颜色及轻微字距变化 | 先查当前结构化run/字距接口并做小样；能实现则原生 | 看到大小变化就跳过原生能力查证 |
| 一个信息区含纹理艺术题字、装饰章和四条标准说明 | 题字与章按需独立图片，四条说明原生；背景不得残留说明旧字 | 因为同属一个区块就烘焙整组 |
| 手写风字体的字形本身已有合法字体且原生回读达标 | 原生；“手写感”本身不等于必须生图 | 只看风格名称，把现成可编辑字体栅格化 |
| 普通宋体名字写对了，回读却成无衬线 | 保持普通文字分类，排查字面/加载链；未解决即该项未达标 | 把技术失败改称艺术需求，用粗黑或图片掩盖 |
| 必须原样保留的照片里有招牌字或指定Logo | 保留受保护的原媒体；只对另加说明作原生判断 | 为提高可编辑比例擅自重画原资产 |

这些是推理检查，不是需要再生成八张海报的任务。选择依据应随视觉特征或能力证据变化，而不是随对象被叫作“标题”还是“正文”变化。用户明确指定对象载体时先遵守该约定；无法同时满足时指出具体冲突，不伪称自动兼得。

这项判断是已有视觉检查的一部分，不增加逐页审批。真正艺术字已经获准用图片时直接执行并说明边界；不能把这项允许扩大到旁边的普通栏目、说明或条款。未被放宽的可改字或指定字体要求遇到冲突时，说明具体对象和选择。

## 原生对象也要承载整页设计

先分清本页的视觉任务。产品页可让原图、超大标题和留白形成主次；证据页可让准确图表承担重心；流程页根据真实阶段建立阅读顺序。不把“原生可改字”执行成每页同一套粗体标题加三栏正文，也不为了显得艺术而削弱数据和条件。

对照母图时，除了字体接近程度，还看视觉焦点、尺度差、文字与图像的关系是否保留。若重组后变得保守，定位是尺度/位置问题，还是载体已经损失字形与气质；只修责任角色，不用不断挪框掩盖字体回退，也不重做整套。克制排版可以适合某些用途，但不能据此宣称达到另一份更强艺术性的参考标准。

一次五页合成商业试用采用了原生大标题与价格、图片艺术背景和两张完整指定原图，说明原生文字可以与画面艺术设计共存。它只支持该组字体和当前后端的这次选择，不证明任意字体效果、导航或WordArt都能无损往返；详见[案例及边界](commercial-trial.md)。

## 面包社导航的具体拆法

用户给出的裁图包含“品牌、菜单、体验、落地”，白色纸纹带、麦穗/分隔符、红色活动纸签，以及放大的白色“体验”。粗黑字和粗白字值得优先尝试原生文本。紙纹、撕边与麦穗可以独立复用，固定四个槽位，活动字的放大不能挤走其他章节。

用户研究包已有原生重建与失败对照。当前JS运行时又在原生样例副本实际完成“体验→试用、75→81pt”和活动态切换到“菜单”，严格导出、保存重开、渲染后，四个框未移动、红签到指定槽、原媒体字节不变。它只证明该基础样例在当前渲染器可用；没有PowerPoint/WPS实测。研究的75/40pt、两字标签预算和装饰素材仅属于该样例，不是通用风格、商用授权或默认模板。

生产时由项目自己的主题、角色与编辑范围定义样式。可执行角色引用、单位、完整状态重设和能力记录见[原生样式源](native-style-tokens.md)。研究装饰不能随公开Skill分发。

## 不混淆格式、后端、渲染与字体

- PowerPoint 应用和 OOXML 格式能表达什么
- 当次获准生成/导入库暴露哪些公共字段，实际写入什么
- 渲染器如何显示，编辑和保存重开后是否保留
- 本机和目标使用者实际有哪些字体，授权是否允许分发/嵌入

当前 workflow 的文本入口是 `scripts/pptx_backend/render_objects.mjs`。普通字符串与结构化run使用不同赋值顺序：结构化文字先设默认样式，再赋带局部覆盖的内容，避免整体setter覆盖run字体、字号和颜色；段落局部间距优先。准确契约见[原生样式源](native-style-tokens.md)，不另造一份排版引擎。这不证明支持所有OOXML/WordArt属性；字段仍须查当前Presentations/实际后端文档和实验，不猜 `stroke`、`warp` 等名字。

缺字体要说明替换后的视觉差异；缺后端功能要说明是当前库未提供或往返丢失，不笼统说“PPT做不到”。未经许可不下载、嵌入或分发字体；只有文件内声明字体族，不能称字体已携带。

文件声明正确也不保证每个渲染器一致。早先两页实作把普通中文角色图片化以回避Noto Serif CJK SC的回读字形问题，用户随后明确指出这种处理不合理。后续核对真实集合字面，单独加载同名SC字面后，原生宋体在实际PPTX回读中正常显示，普通文字全部恢复可改字。该实例只证明这一字体/运行时组合的修正，不说明所有TTC或后端均相同；技术字体回退不能作为普通文字图片化的通用理由。分别记录实际预览、目标机字体依赖和未测应用。

不能为了“全原生”把文字转为轮廓路径后还说可逐字编辑。采用艺术文字图片时记录准确文本、图片化依据、编辑边界和局部替换方式。后端由实际可用工具、权限及经验证能力选定；缺接口时记录具体版本和能力缺口，不虚构支持。原生对照通过且编辑职责匹配后，不再把这些文字送图片模型。
