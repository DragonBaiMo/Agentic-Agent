# workflow：图片设计优先的分层 PSD / 可编辑 PPTX

这是 workflow 1.4.1-rc.3 候选版，名称仍为 `workflow`。支持完整图片设计、语义素材提取、真正分层 PSD 和可编辑 PPTX。旧 PSD 项目、命令与 manifest 继续可用；PPTX 使用独立 deck.json。rc.3补充标题来源与艺术/原生角色，增加自动证明并严格拒绝未知结构的有界依赖保全CLI；它不替代Artifact Tool文字作者，也不是任意PPTX无损编辑器。原生产脚本、依赖和下述完整流程继续保留；本批变化见配套《本批改进.md》。

先读 `SKILL.md`，它现在直接给出入口、工具前提、工程树，以及每阶段的输入、动作、输出、前进条件和命令。第一次用新需求做图可跟随 `references/new-task-walkthrough.md`；不是只重建 Future Lab。

具体问题诊断与两个源包逐项能力去向，在 `references/source-capability-map.md`；它明确区分保留、恢复、替代与有意取消，未把程序测试当成说明可用性的证明。

## 1.4.0 怎样减少无谓等待

方向确定后，让余页完整母图与代表页提层/重组交错；一页母图通过检查就开始该页提层，每项返回先保存登记。使用有界窗口而非无限批量；只有最终全套组装和审阅才汇合。具体执行入口、原生工具宿主接法和恢复命令见 `references/rolling-scheduling.md`。

本地异步基准已验证滚动消费行为，没有证明图片服务变快或六页作品已经能在几十分钟内完成。真实端到端复测口径、目标和剩余验证见 `变更与验证.md`；不能减少页数、原生内容、艺术质量或关闭实际回读来达标。

## 一直保留的设计与编辑原则

允许生成模型存在合理误差。位置和大小略有偏差时，先调整素材而不是强迫重生。原图整体关系要保住，明显错位和错字要修，但不追逐不现实的 100% 像素一致，也不拿一个自动算出的分数替代“看起来对不对”。

现在保留两个真正影响结果的沟通节点：完整母版/视觉方向，以及推荐图层架构。可以合并一次展示，用户不必先懂 PSD。说明预计叶层数、每层能改什么、哪些是图片字、哪些可直接改字，主体/背景/效果怎样独立。用户明确“全自动、你决定、直接做完”则记录推荐方案继续，不逐步追问，也不伪造用户批准。计划重大变化才重新确认。

完整设计更敢于在主题签名、尺度、材质或展示字形上做选择，其余信息保持可读。艺术字独立模板，避免无差别带入玻璃/柔光描述；玻璃透明性用 Alpha 分布和真实叠放判断。新增实际调用公开参数记录、运行环境/字体路径预检和只读行宽校准工具，仍不把这些数据当艺术评分。

不是把两个 Skill 原样堆在一起：保留 LayerForge 的完整设计、语义所有权、单一视觉任务、透明材质保护和局部修复；用已经实际做出未来实验室 PSD 的代码作为组装核心，并补上混合模式、透明度、显隐和图文交错顺序。

## 给智能体使用

将解压后的 `workflow/` 作为标准 Skill 提供给支持 Skill 的宿主。启用方法取决于你的平台；本次没有替你安装，也没有创建或启动你的 Codex 任务。

示例请求：

> 使用 workflow，把这张图做成真正分层的 PSD。保留整体感觉，背景、主体和文字要能分开操作；位置和大小允许合理微调。特殊艺术字保留图片形态，普通说明用可编辑文字。直接做，交付 PSD 和预览。

没有必要照抄这个文字策略；如果希望所有文字都是图片，或全部可编辑，应明确告诉执行者。包内两种能力都保留，但复杂可编辑文字有实际限制。

## 文件入口

- `SKILL.md`：简短默认工作流和参考路由
- `references/pptx-production.md`、`references/pptx-tools.md`：PPTX 全流程、实际组装与回读编辑
- `references/rolling-scheduling.md`：多任务逐项消费、真实计时、重试与恢复
- `references/visual-production.md`：怎样判断图层、定位、容错、停止修复
- `references/interaction-and-layers.md`：两个可合并确认点、推荐分层、全自动默认与重新确认边界
- `references/font-calibration.md`：字体身份、TTC、基线/字宽/字距与实际命令
- `references/tools-and-prompts.md`：工具职责、真实调用参数示例、干净提示词
- `references/manifest.md`：安装、可运行命令、配置格式
- `references/limitations.md`：文字、字体、蒙版和 Photoshop 验证边界
- `变更与验证.md` 与 `validation.json`：改了什么、保留什么、实际测了什么
- `examples/future-lab.json` 与 `assets/future-lab/`：可直接重新组装的历史生产实例，不是供以后套版的模板

## 可运行演示

按 `references/manifest.md` 安装依赖与配置字体后，运行组装和独立验证命令。会输出 1024×1536 的 Future Lab PSD，包含 3 组、11 个叶层，其中 8 个原生文字层；图片背景、钴蓝环和橙色核心各自独立。

这些素材来自先前已经完成的真实图像模型调用，本次没有为了验证代码额外生成图片。历史原始艺术参考没有文字，成品另行排版；新版从零生产则要求先把完整文字方案纳入设计。演示重建的基准是已经交付的完整成品 `reference-preview.png`，不能用这次重建成功倒推当年的每个生产步骤都符合新版。

交付一个 Skill ZIP，是可复用工具和做法，不是一套含所有运行时、字体和账号的免安装软件。主智能体还需要真实图片工具、文件访问和代码执行能力。
