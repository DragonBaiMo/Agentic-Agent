# 工具与提示词

先满足[全局图像工具前置](dependencies-and-start.md#必需的图像工具)。本页描述工具分工，不提供无生图工具的替代入口。

## 主模型与图片工具怎样交接

主模型保有需求、事实、设计与验收责任。先把业务材料转成准确内容和整页视觉任务，再亲自组织图片调用；图片模型通过宿主工具接收当前任务和真实参考，生成/编辑母图及语义资产。生成成功只代表有返回，主模型须查看它，纠正错字、错数、残影和风格偏离后才选用。

采用母图后，主模型定义每份图层的owns/excludes、所属文字、透明性、位置和遮挡关系，调用图像工具逐份生成/编辑；用户指定原件直接保真复用。代码按已选设计轻量组装、设置精确数据与坐标、写入真实格式并回读渲染。主模型再逐页打开成品图像，与母图和内容源对照，决定局部返修或交付。委托其他执行者时，负责交付的主模型仍须亲眼看最终页面，不能把自述通过当视觉证据。

代码不负责发明艺术画面，图片工具也不负责工程目录、权限或最终验收。调用参数、返回文件和视觉结论分别记录；不把准备好的DRAW、代码预览或历史调用称为本次已执行图片生成。

## 什么时候用什么

新项目的实际准备入口是 `project.py init`，不是先运行 Future Lab 例图。逐张生图时执行 `visual_job.py`；`prompts/` 是当前参数化模板，本文例句用于理解写法。`record_asset.py` 保存真实返回和来源，`project.py compile` 才把计划接到下表的 assemble。

| 工具角色 | 何时使用 | 实际做法与边界 |
|---|---|---|
| 主智能体 / 文本模型 | 需求与材料理解、内容及设计决策、图片调用、拆层、编辑约束和逐页判断 | 实际组织母图/图层调用并查看返回和成品；维护计划，不把猜测写成用户批准 |
| 图片生成 / 参考图编辑 | 完整艺术方向、干净背景、物体补全、独立艺术字、光影 | 每次生成一份语义素材；明确实际参考图、画布、位置和透明要求 |
| 图片查看工具 | 生成后和合成后 | 查看真实像素；不能仅靠文件名、Alpha 或成功响应判定质量 |
| `probe_assets.py` | 不确定画布、透明性或物体范围 | 只读尺寸/Alpha 极值、分布和包围框；不改图、不批准艺术质量 |
| `measure_text.cjs` | 普通字需要保留母版行宽关系 | 按真实字体和渲染规则测 advance，给可选字距建议；不替代看图或 Photoshop 重排 |
| `assemble.cjs` | 素材已基本合适，需要微调坐标及打包 | 裁透明空白、平移、缩放、混合和原生简单文字；写 PSD 与 PNG |
| `verify_psd.py` | 已写出 PSD | 独立解析技术结构；可重建合成、生成对照和隐藏视图，不设视觉分数门禁 |
| 真实 Photoshop / 可用编辑器 | 用户要求实际应用兼容或高级文字/蒙版 | 仅在环境真实支持并已获授权时操作；解析器不是 Photoshop |
| 文件交付工具 | 成品验证后 | 按当前环境的真实上传/保存接口交付，保留确实可访问的文件引用 |

额外可选工具：`review_assets.py gallery/viewer/move` 用于候选比较、真实层切换和移动诊断；`project.py status/snapshot/restore` 用于续做/回退；`deliver_project.py` 用于可继续编辑的工程源包。这些不产生新的图片模型调用，也不自动批准艺术结果。

技能不附模型、API Key 或 Photoshop 权限。先检查当前工具 schema及全局前置；工具名称或品牌不证明它支持 PSD 写入、同画布控制或透明输出。

## 图片模型只接收当前视觉任务

主智能体负责工程，图片模型负责这次图像。不要把 Skill 全文、测试要求、PSD 目录树、交付 ZIP 或软件面板描述塞进生图提示词。只传：要画什么、保留哪些对象/文字、参考图、构图、颜色材质、尺寸和透明性。

完整作品参考写法：

> 创作一张 1024×1536 的原创未来实验室海报。冷白空间、钴蓝悬浮装置、橙色玻璃核心。顶部留有大而清楚的标题区域，文字与画面形成统一构图。画面文字仅为：未来实验室；让想象发生；FUTURE LAB。标题厚重简洁，信息清晰，留白克制。只输出整张作品本身。

独立物体参考写法：

> 编辑附图，仅保留中央钴蓝陶瓷与银色金属环形装置。保持参考图中的倾角、外形、颜色、原大小和大致位置，不把物体放大居中。画布 1024×1536。移除玻璃球、文字、背景和地面投影；遮挡部分自然补全。装置外真实透明。仅输出这一份完整画布图像。

干净背景参考写法：

> 编辑附图，保留冷白空间、地面与原有光线。移除装置、球体、前景和所有文字，自然补全原位置背景。画布与原图相同，整幅不透明。保留空间明暗关系，不新增装饰。

艺术文字使用独立 `prompts/typography.txt`，不继承其他素材的玻璃/柔光描述。参考写法：

> 编辑附图，仅保留顶部标题“未来实验室”。保持原来的字形、排布、颜色、材质和位置。画布与原图相同，其余区域真实透明；这一图像只包含这五个字。

上述例子是写法说明，不是版式模板。实际主题、对象、字数和文案以用户项目为准。非文字素材不用携带海报全部文案。

## 当前宿主的真实调用示例

若可用工具正是 `image_gen.imagegen`，其参数形状如下；不保证其他宿主同名。

```javascript
// 新作品：不提供参考图参数
await imagegen({prompt: currentVisualPrompt, transparent_background: false});
// 编辑：已实际查看本地参考图；这里只传当前视觉正文
await imagegen({prompt: currentVisualPrompt,
  referenced_image_paths: [actualMasterPath], transparent_background: true});
```

本环境可通过 `tools.image_gen__imagegen` 调用上面的参数。只在图片没有本地路径时才按该工具要求使用 `num_last_images_to_include`；它不能与 `referenced_image_paths` 同传。真实调用可能返回平台图像而非已保存文件，按当前宿主支持的保存方式获取文件，不能虚构路径。

依赖上下文推断的图片工具只能用当前公开接口；写在请求文件中并不等于工具实际收到。记录已知的实际提示词和返回路径；后台提示词不可见就记不可见，不补造。每个独立素材可以并行调用（若宿主允许），不要让并行工人读到过时母图。

## Adobe 的实际边界

历史制作时检查过 Adobe 接口，但没有发现任意写入分层 PSD 的接口。一次把母图送到 Adobe 资产上传工具的尝试返回 Forbidden / asset not accessible；未绕过该拒绝。成功路线是图片模型生成 + 本地组装。这不是 Adobe Photoshop 已操作的证据。

Adobe Express 的模板设计入口不适合用户要求原创、不套模板时强行使用。若现有 Adobe 插件确实提供可用的生图/背景移除/字体查找功能，可在对应需求和权限范围内使用；是否成功以实际返回为准。上传被拒绝时停止该拒绝动作；全局图像工具前置仍成立时，才可继续已获授权且不访问被拒资产的独立本地工作。若必需图像工具已不可用，整个Skill暂停，不借本地打包豁免。

`examples/future-lab-prompts.json` 保存原制作的四次实际提示词，仅作历史可复现证据；其中旧式“无字母图”和工程字眼不是新版的推荐写法。当前生产以本文和 `SKILL.md` 为准。

完整设计取舍、图层来源、漂移注册、Adobe 失败与层序排错的历史过程见 [Future Lab 案例](future-lab-case.md)，不是仅给现成图片重建。

## 准备快照与实际调用记录

`jobs/J01/request.json` 永远描述准备时状态，保留 `prepared_not_executed`；不是当前任务未完成。`receipts[].request` 保留该快照兼容旧项目，request_scope 明确其含义。新加的 `receipts[].execution` 描述实际收到/导入的文件，status 为 result_recorded；是否采用仍看外层 status=usable/rejected。

如宿主公开本次实际提交的参数，可在项目 jobs 中保存一个精简 JSON，传 `record_asset.py --execution "$PROJECT/jobs/J01/actual-public-arguments.json"`：

```json
{
  "prompt": "本次真正提交的视觉正文，不是想象中的后台正文",
  "referenced_image_paths": ["reference.png"],
  "transparent_background": true
}
```

三个字段分别对应实际 prompt、实际附件文件（相对该 JSON 或绝对路径）、实际透明参数；新图无附件时省略 referenced_image_paths。脚本保存正文、附件名称/字节哈希及透明参数，不保留本机绝对路径。必须在 reference 字节改变前登记；附件无法落盘或调用未公开这些信息就省略 --execution，并在交接说明，不补造。使用最近会话图片而没有本地文件时不要编一个附件路径。

这份记录标为 caller_reported_public_arguments，只代表执行者能看到的实际调用参数，**不能证明后台已按预期使用参考图**。call-id 不可见就保留 not_exposed；effective_backend_prompt/backend_binding_observed 仍记 not_exposed。不要传完整工具响应、账号信息、密钥或凭证，未知字段会被拒绝。旧版 requested_visual_prompt 是准备正文，不能把它当实际提交正文；实际差异保存在 execution 中。

## 柔光与玻璃的专门写法

柔光层：只保留光晕/薄雾的形状、色相与原位置，其他对象透明；保留柔边和低 Alpha 尾部，不加入实体背景。effect_box 可比主体框大，测量低 Alpha 范围只用于理解，不删像素。

玻璃层：明确瓶壁、液体、标签分别属于谁，保留折射和半透明；补全被丝带等遮挡处，不把母图背景烘焙在透明玻璃后。若模型不可避免留下特定背景折射，应看叠回后的实际效果，说明移动到完全不同背景的局限，不承诺物理正确重建。
