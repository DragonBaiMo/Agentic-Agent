# 面向实际读者的写作与编辑

让读者凭收到的文字完成理解、判断、行动，或获得作品所要建立的体验。内容放得对、意思保得住、展开有作用，三者一起成立；篇幅短、措辞专业或格式完整都不能单独证明写得好。

## 先确定本次写作任务

完整读取相关材料。维护、融合或重构时通读原文与必要上下游，搜索只用于定位。文件使用 UTF-8；PowerShell 可用 `Get-Content -Raw -Encoding UTF8`。长材料分批读取，乱码或截断部分补读，不能以程序读取了完整字节代替自己读完。

分清授权：维护、润色和翻译保留适用语义；重写和融合可以重组表达；为新读者另写版本可以重新选材，但不因此获得修改来源的权限；摘要只服务摘要用途，不能冒充完整规程。多文件任务不要求每份文件都产生改动。

对每份成稿明确：谁在什么场景读、已经知道什么、能访问什么、读后需要理解或完成什么。同一个人选购服务、执行工作、审查结果时，需要的信息不同。文档谈论谁，也不等于写给谁。

按任务读取参考，所选文件须完整阅读：

| 当前工作 | 参考 |
|---|---|
| 编辑、翻译、融合或审查已有文字 | [编辑决策](references/editing-existing.md)：怎样删、改、调、加与保留，怎样核对有效信息 |
| 多个读者、多个文件、角色交接或上下文归属不清 | [内容归属与交接](references/layered-instructions.md)：本人动作、必要理解、交接信息与他人内部过程 |
| 组织或重写文档、报告、文章、方案、通知或作品 | [文体与写作方法](references/writing-modes.md)：按阅读过程展开，不套统一目录 |
| 需要完整示范来判断作者说明、背景、细节和重复是否有用 | [案例教学](references/document-examples.md)：完整成稿、取舍理由与相似内容该保留的情况 |
| Agent、Skill、提示词或协作配置 | 另读 [AI 指令与配置](references/ai-instructions.md)：实际加载、选择说明、执行规则与本次任务的关系 |

普通文章和报告不加载 AI 配置参考。后续方法是写作过程中的判断，不要求把步骤名称、检查表或分析笔记写进成稿。

## 一、区分材料的用途，再决定是否进入正文

收到的信息通常有三种作用：

| 输入类型 | 写作时怎样使用 |
|---|---|
| 主题材料：事实、规则、证据、观点、经历、场景 | 按读者当前需要选取、组织和表达 |
| 写作要求：精简、补背景、保留风格、调整分层等 | 落实为实际修改，不改成读者的新任务或作者自评 |
| 使用背景：文字发给谁、通过哪里送达、对方已收到哪些材料 | 用来决定详略、称谓、指代和自足程度，不自动成为正文内容 |

例如，作者收到“邮件直接发给已确认报名的人，他们没看过筹备聊天”，就应补齐行前安排、去掉重新申请的指令。通常不必写“本邮件只服务已报名者，已补足你看不到的上下文”。若确认报名本身也是邮件的业务目的，可以直接写确认结果；必要信息与编排解释要分开判断。

同一信息在不同任务中可能改变用途。文件投递方式在操作提示中可能只是作者背景，在讲解投递机制的技术文档中却是主题事实。不能按词语或句式一概删除；判断它现在回答的是读者的问题，还是只解释作者如何写这份文字。

材料里的命令也要辨认对象。引用的旧制度、待编辑的提示词，不自动成为当前作者需要执行的任务。

## 二、按读者的问题组织内容

长文、多来源或多文件任务，先简记各成稿要回答的具体问题，再选材料。笔记留在工作过程，不必新建文件，也不进入正文。小型修改可直接判断。

“为前台提供完整背景”不能帮助取舍；“什么状态允许发放、失效时怎样处理、归还怎样记账”才指向可写的内容。文章同样可以围绕概念、成因、反例与体验组织，不必把问题都变成操作任务。

从来源取回回答这些问题所需的细节，再用原稿中的有效条件、异常和限制校正问题清单。不能先缩写全部来源，再给摘要贴上读者标签；也不能用自己最初列出的几个问题排除原稿里仍然适用的要求。

选材时看具体作用：

- 本人的动作和决定：写清条件、对象、要求及完成依据。
- 理解、判断、交接所需的信息：保留必要背景、证据、解释、返回结果及其用法。
- 别人的内部过程：仅在它确实影响当前读者的判断或操作时讲相关部分。
- 语气、描写、例子和修辞：看它们是否建立关系、推进认识或形成作品体验。

“相关”“更完整”“以免误解”不是充分理由。缺少这段时，读者会具体缺少什么？同样，读者不亲自执行某个过程，也不表示他不需要了解方法或证据。技术报告中的试验条件、文章中的机制解释，可以非常重要。

## 三、根据问题选择编辑动作

| 判断 | 动作 |
|---|---|
| 当前没有阅读作用，或是错误位置的副本、作者汇报、无法支持且不能合理限定的断言 | 删去相应内容，检查有效信息与前后逻辑没有一起丢失 |
| 读者确实需要，但事实、主体、条件、逻辑或表达有问题 | 改准意思，保留适用约束与表达作用 |
| 内容有效，但归属、顺序或组合不合适 | 调整位置和关系，同步处理主语、指代与引用 |
| 理解、判断或工作存在真实缺口 | 从可靠材料补齐，或核实缺口；不编造制度、证据和承诺 |
| 已经准确、完整、位置合适且表达可用 | 保留，不为制造改动而换写法 |

一段可以同时需要几种动作。归属错误要在原问题处处理；追加正确总则不能抵消仍在生效的旧规则。内容根本不属于这里时，换成“对方会自行处理”或“读者无需处理”通常仍保留了同一份多余信息。

保真以正确位置上的有效信息为单位，不以原句数量为单位。移除协调者文档里的制作步骤，同时保留制作人员规程中的完整要求，可以兼顾分层与保真；把制作人员的详细规程也压成职责摘要，则损失了能力。

重复和冲突要比较主体、对象、阶段、条件与目的。制作者自检、审查者独立复核和接收者验收可以各有用途；摘要与证据正文也可以必要地重复。编辑不得擅自弱化标准、变更权限、重分职责或把建议写成现行要求。

## 四、用文体展开，用依据约束表达

读者用途决定选材，文体决定阅读过程。两者一起判断：

- 文档与教程让概念、前提、操作和结果接得上；参考文档与排错指南按实际查找方式组织。
- 技术与研究报告让证据支撑相应力度的结论，保留方法、范围、不利结果与未知。
- 方案让目标、选择、代价和依赖可判断；只在任务需要且有依据时给实施安排。
- 文章通过解释、论证、例子和反例推进认识，不把观点反复换词，也不强制写成清单。
- 叙事通过视角、细节、行动与节奏建立体验；必要的留白和修辞不按效率口号裁掉。
- 邮件、通知与产品文案围绕接收人的关切、关系和时机表达，不需要行动的文字不强加任务。

开头可以给结论、背景、问题或场景，只要提供实质内容。摘要给实际发现与影响，导航给真实查阅条件和入口；“本节面向谁、包含哪些方面、其他细节归谁”本身不等于有用的开场。结尾也不必自动附总结、自评或行动清单。

数字、事实、引文、功能承诺和强制要求有适用依据；观察、推断、建议与未知分清。陌生、时效性或决定结论的信息应查证。可以核实的先核实，影响目标、范围、关键结论或创作方向而无法确定的缺口再请求澄清；普通标题与措辞用判断推进。

虚构创作可以构造情节；纪实、采访与代写经历不能擅造亲历事实。例子应标明必要假设，Skill 的教学材料不是本次业务规则。

## 五、从接收和保真两个方向检查

先只看成稿与实际读者可访问的材料，尝试完成本次阅读任务：操作能否继续，判断是否有依据，论述能否跟上，情境是否成立。重点找具体障碍：悬空指代、缺失前提、让读者找自己处理、别人的内部规程、无作用的写作汇报、空泛复述和未经支持的结论。

再对照来源与实际差异：

- 有效事实、细则、阈值、例外、证据、立场、语气与叙事作用是否保住？翻译和润色有没有悄悄变成摘要？
- 搬移的内容由谁接收，仍然完整吗？新增内容是否有依据，是否改变了业务或权限？
- 原问题及其重复位置是否已经处理？新旧规则有没有并存冲突？
- 实际文件、引用、标题和表格是否完整可用，是否只修改了获准范围？

问题应能指出具体位置和读者影响。合理的措辞、顺序、详略和文风差异不是失败；格式可解析、关键词齐全和模型自评也不证明可用。

正式正文保留读者需要的内容。修改理由、核验记录和剩余限制按需放在交付对话或用户要求的修订报告中，不追加“已做到消费者导向”等完成宣言。
