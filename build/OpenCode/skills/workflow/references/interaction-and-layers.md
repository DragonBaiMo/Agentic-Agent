# 关键确认与分层架构

## 两个节点，解决两个真实决定

1. **母版/视觉方向**：让用户看到包含最终文字方案的实际完整图或PPTX代表页渲染，选择值得继续做的方向。原生方案不强制先生母图。推荐一个有把握的方案，解释它的主题签名与阅读顺序，不强制做三张候选。
2. **图层架构**：在大量拆层之前，说明交付后能改什么。给出推荐的叶层数量、分组和每层编辑用途，解释文字形态与背景/主体/效果依赖。用户只需选择“按推荐做”或指出真正要独立编辑的部分。

两个节点通常一起展示，一次答复即可；用户已经批准母版则只问架构。输入是用户已选中的完整图时，不再重复确认视觉方向。用户已清楚指定拆分和文字处理时直接执行，不重复问已知答案。每张素材、每次定位、每次正常构建不再逐一询问。

保留 master_only：用户明确“只先让我选母图，之后你来做”时，只在选稿暂停，获选后按已授权范围自主分层；它控制停点，不自动改变成品范围。用户本来只要母图而没要 PSD，则交付母图后结束。

## 用推荐方案问，不考用户 PSD 知识

可以这样说（内容必须换成当前作品）：

“我推荐按这张母版做，分 8 个可操作图层、5 个文件夹：完整背景、标本、投影、艺术标题各 1 层，4 条说明分别可改字。标题保留图片字形，可移动/缩放但不能直接改字；标本能独立移动，内部折射仍带有原背景色。你更希望保持这套效果，还是优先让标题也能改字？”

不要只问“需要多少图层、怎么分？”然后等用户设计架构。按编辑收益给推荐方案，必要时最多补一个有实质区别的选项：更少层易用、更细拆方便调节。明确层数按**叶层**统计，文件夹数量另列；不要把组和隐藏整张母图计作额外可编辑层。

图层提案至少回答：

| 决定 | 用户能理解的内容 |
|---|---|
| 编辑目标 | 会不会换背景、移主体、换文案、调光或做尺寸变体 |
| 数量/粒度 | 推荐多少实际叶层，哪些合并，为什么值得拆开 |
| 内容归属 | 每份文字、物体和效果只由明确的层拥有 |
| 文字 | 哪些是图片艺术字，哪些是可改字的 native type；复杂效果的代价 |
| 独立关系 | 背景是否补全、主体遮挡是否补全、投影/光效是否单独，玻璃内折射是否烘焙 |
| 验收 | 哪些层必须能单独隐藏/移动，哪些文字必须逐字准确 |

## 全自动授权时的默认方案

“全自动”“你决定”“直接做完”才是跳过这两个设计停点的依据；不把沉默、工具成功或计划默认值当授权。记录用户原话或可核实的消息引用，以及执行者的方案和取舍。全自动授权不跨越权限、费用或外部上传边界。

没有指定粒度时，按有用编辑动作做**最小充分分层**：

- 1 个完整连续背景；前后不同景深只有确实需独立编辑才拆
- 每个需要移动/替换的主要对象1层；实物表面不可分的标签可随主体并记为图片文字。单独排版的普通费用标签/栏目不因“固定”就随整组图片化
- 需要单独调强度的投影/光效各 1 层；自然表面纹理留在对象内，不机械拆满七类
- PPTX逐文字对象判断造型和原生能力：普通标题、导航、固定栏目和说明用匹配的原生字体；特殊艺术造型才选择原生艺术字或独立图片。同区块可有艺术图和原生正文，不按标题/固定文字整组图片化。字体故障先查真实字面与加载。PSD仍按已验证的简单Type层与语义图片边界选择，不把PPTX能力迁移过去
- 可能再次露出的遮挡合理补全；前后交错按编辑目标决定拆为两层或保留连体

层数由这些动作算出，**没有统一 8 层门槛**。例图的 8 层只是实例。展示或在交接中保留推荐方案、实际结果与变化。全自动中的“执行者选定”不等于“用户视觉批准”。

## 计划记录：可续做，不造审批引擎

在 plan.interaction 中使用已有 mode（staged/master_only/autonomous）、stop_at、user_visual_approval；新增可选 notes/decisions 只是执行者记录，代码不签批。推荐结构：

```json
{
  "mode": "staged",
  "stop_at": ["master", "layer_architecture"],
  "user_visual_approval": false,
  "notes": "默认合并展示两个节点，尚未收到选择",
  "decisions": []
}
```

每条 decision 可写 checkpoint、decision_by（user/executor）、basis（原话/消息引用或自主判断依据）、selected_master、layer_summary、remaining_limitations。只记录实际发生的决定，不复制示例假造消息 ID。细分架构直接体现在 plan.layers/owns/excludes/copy_ids/occlusion；不要重复维护第二套机器状态。

旧版 autonomous 计划不会被工具强制改写。续做时核对原有授权；来源不明且涉及尚未确认的重大设计选择时补一个问题，而不是凭该字段推断用户意图。

## 何时重新确认

需要：重换已选视觉方向/主题；准确文案发生实质变化；把未被用户放宽的可改字承诺改成图片；合并用户要求独立的主体、投影或效果；把可换背景玻璃降为明显烘焙底色；超出明确费用/尝试范围；用户要求的精确层数变化且影响其下游流程。先说变化、影响、推荐处理，一次问清。已获准的特殊艺术字按该对象取舍执行，不重复确认；“美观优先”或接受部分艺术图不能扩大成普通文字图片化授权。交付说明真实编辑边界。

不需要：既有方案中的轻微平移/等比缩放、字号/字距/基线校准、透明软边修复、同一责任层重试、只用于组织的文件夹改名、没有减少编辑能力的少量叶层增拆（用户未固定层数时）。记录实际变化即可。明确全自动且取舍仍在授权范围内，继续执行；关键能力做不到时不能用“全自动”掩盖。

用户暂停/改变方向时保存现有素材与 plan.resume_note。等待决定期间可做不依赖选择的字体检查、文件整理、依赖预检，不继续耗费尚未选定方向的大量生图。
