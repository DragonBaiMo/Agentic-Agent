# 既有PPTX的工作簿丢失与原依赖恢复

当任务只改已有PPTX的一处文字，但导入重导出丢失了未改图表的原工作簿时，参考这个有界案例。它不是通用无损编辑器，也不授权用低级ZIP改字绕开当前Presentations作者路线。

## 反例

陌生执行者只收到5页PPTX及“第5页含税报价5200改5600、相关备注同步，其他内容和工作簿保持”的请求。它用当前Artifact Tool导入、定位原生对象、改两处文字并导出。画面仍正常，前4页PNG不变，但原第3页图表丢了embedded workbook、chart rels、externalData及xlsx内容类型声明。严格finalizer报native_chart_workbook_contract_failed，正确阻止交付。

因此，图面不变和文字可编辑都不能证明工作簿保全。此首轮应记为阻断，而不是独立成功。

## 本例采用的恢复边界

先核当次Presentations的作者与修复要求。本例读取到的template_following要求在工具丢失必需元素时调查并尝试恢复；native_evidence和finalization要求保留用户指定的原工作簿。后续在明确该边界后，仍由Artifact Tool完成文字作者操作；后处理仅恢复它丢失的原依赖，不重新编写幻灯片文字，不创建新工作簿快照，不关闭检查。

能证明以下事实，才继续本例这条路径：

1. 源图表与导出图表对应唯一；仅移除源externalData后，两棵XML语义树相同，类别、数值缓存、轴、样式及工作表引用一致
2. 原chart rels中的内部目标真实存在，导出中明确缺失；本例只有一条工作簿关系，目标路径可原样恢复
3. 原工作簿字节可读并已固定哈希；本例是无单元格公式的单表快照，不能据此声称复杂公式、宏或外链均已验证
4. 源中原有的xlsx内容类型声明唯一，导出中缺失；只补回该原声明，不覆盖整份Content_Types而破坏其他导出关系

随后在作者导出稿的新副本上恢复原chart XML、chart rels及workbook字节，补回原声明。比较后处理前后的slide与notes字节，确认没有第二次内容作者操作；再按原严度运行finalizer，检查原生chart、工作簿关系和真实数据，回读全部页面并比较未改内容/布局/媒体。对应不唯一、缓存不同、目标冲突、关系含外链或需要猜测新关系时停止，不把本例套上去。

## 实际结果与未完成项

本例恢复后严格finalizer通过；原chart、关系和workbook均与源逐字节一致，所有原媒体身份保留。前4页PNG不变，第5页变化限于原价格框；Artifact Tool作者生成的slide/notes字节在后处理前后未变。源文件未覆盖，也没有新生图。

这属于“独立首轮正确阻断、指导后有界恢复通过”，不是候选已具备任意PPTX自主无损编辑。一个早期直接对源ZIP改文字的实验虽技术通过，仍被留为未批准诊断，不作为交付路线。

rc.2时的修复实验只有18项核心测试，语义预检/CLI全链、文件系统异常和独立lint/typecheck未完整覆盖；调用者自填proof布尔值也不能构成可靠证明。该历史实验继续留在证据中，不作为通用API。

rc.3另提供[有界自动保全工具](../tools/bounded-pptx-preservation/README.md)：在同次调用中读取源与作者输出、证明身份和全部缓存引用，再恢复原依赖，严格finalizer及输入身份复查通过后原子发布。支持范围具体限定为唯一slide owner、同chart路径的单barChart和五部件inline静态xlsx；无styles/sharedStrings、公式、宏或外链。不是一般Excel单表文件都能使用。85项测试覆盖正常、拒绝、文件失败及包装器失败；真实案例保持原依赖且回读画面不变。Python核心模块经独立lint、类型检查与覆盖率检查，包装器另有真实finalizer和失败注入验证。

不匹配这条窄路线时保留原件，继续分析当前工具的受支持保全路径或报告具体阻断，不能删校验让其通过。若宿主以后支持可靠保留原依赖，应优先采用其受支持路径并重新验证。

没有PowerPoint或Google Slides目标应用实机测试。这个恢复不修复宿主库本身；文件再次经未经保全处理的同一导出路径时，仍可能再次丢工作簿。
