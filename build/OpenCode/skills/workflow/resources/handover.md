# 项目交接

按实际项目填写适用项，删除空的提示文字。此文件帮助接收者从源包继续工作，不替代已存在的内容和数据文件。

## 当前成品与状态

写明格式、最新构建、源文件及预览的相对路径。PSD 列 PSD/PNG；PPTX 列 PPTX 和实际导出的 PNG/PDF；双格式分别列出。状态填写 final / review / diagnostic，并区分执行者判断与用户实际批准。诊断包明确缺少什么成品，不暗示已完成。

## 内容、标题与原媒体

指向准确文案、数据及来源文件，注明关键条件和仍待决定的问题。标题列用户逐字指定或主模型拟定、准确字面、固定/常改、原生/艺术对象及可改范围。用户指定图、Logo 或视频列原件、对象/页位置、使用约束与已核实的保全证据；封面图或 poster 不能写成视频播放已通过。

有后续业务变更时，列当前决定与原 brief 的优先关系，以及影响哪些格式和对象；旧版预览、母图和报价记录注明历史用途。当前入口应能直接找到新事实，不要求接手者从聊天里猜哪一版有效。

对本次常改事实写出具体权威字段、派生显示方式和实际对象。例如日期由哪一处同时供两格式读取，报价数值如何得到显示文字，哪些文件是构建输出。存在人工维护副本就明确列出，不能把计划中的绑定称为自动同步。

## 能怎样编辑

- PSD：实际组/叶层与职责；哪些是可移动像素艺术字，哪些是当前后端支持的 Type 层；背景、主体、投影/效果是否独立
- PPTX：对象名与页码；哪些文字/数据可原生改，哪些艺术字只能整体移动或替换；母版、版式和普通页对象的实际入口
- 两者共有：选中母图、语义素材路径、文字所有权和重要遮挡关系；与原推荐架构的有意义差别及依据

玻璃或柔光仅在实际存在时说明：外侧透明与内部透射是否分别成立，折射烘焙时移动、换背景有什么限制。不把一个独立 cutout 称为物理透明重建。

## 字体和可重建入口

写出真实字体 family / PostScript 名、准备方式及已观察到的渲染差异，不分发无授权字体。列当前依赖版本/lock、所需 Skill、运行时如何按当前宿主发现。给出本项目实际执行过的相对路径命令及工作目录，注明生成的新输出位置：

- PSD：plan/manifest、compile、assemble 与需要的验证入口
- PPTX：deck 的 plan 参数、content/data、assemble_pptx 及实际使用的编辑或验证入口

同一源包在另一解压位置的资源查找或重建结果要按实际记录；未测则写未测。原素材完整时重建无需重新调用图片模型，包不含运行时就不称免安装。

## 实际验证与已知差异

列实际做过的解析、回读、重建、显隐/移动、改字/改数据及保存再开，并指向对应文件和对象名。实际看过哪版预览，有哪些有意义的布局、轮廓或字体差异。目标应用分别记录 Photoshop、PowerPoint、Google Slides 是否真的打开和修改；工具解码或渲染不能写成桌面实测。不用相似百分比代替艺术判断。

## 下一动作与未完调用

指向当前 plan/manifest 或 deck/data、来源记录和 resume；写已可用素材、缺项、下一具体动作、等待谁及已授权范围。未完成的图片/构建/上传分别记真实 job/receipt/状态；未知结果先核实，不重发。同工程有未知写入时注明当前责任人及待协调事项，不假设旧执行已停止。

## 可访问文件

列成品和源包的大小及实际附件/Library 引用。保存成功与聊天发送成功分别记录。大包失败时先交可用成品及紧凑源包，保留完整包和真实错误；不猜上传阈值，不删除正式产物掩盖失败。
