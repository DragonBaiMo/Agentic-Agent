# PPTX 的实际编辑边界

## 已落地的对象

本后端写真正的 PPTX：独立图片、文字、图表、表格、共享 slideMaster 背景与各页 slideLayout。图片有语义名称和说明，不用隐藏整页母图增加虚假层数。必要数据图/表保持原生，不以截图替代要求可编辑的证据。

艺术标题、固定导航和艺术数字遵循原生达标优先。用户明确选定图片对象或复杂字形超出当前经验证能力时使用语义raster PNG，路线不确定才做一个代表对照。图片艺术字能移动、缩放、替换，不能逐字输入，也不是可编辑字体轮廓。原生文字有字体依赖，未嵌入字体时目标机可能替换、重排。图片字不会随主题字体改变。

背景在共享母版，fixed_layout 艺术对象在各页版式，普通页选不到它们。通过母版/版式视图编辑才是承诺的入口；不是锁死或丢失。当前版式按页创建，不提供自动跨页编辑同一版式族的全量主题引擎。

紧裁只缩掉外围透明留白。复杂轮廓内部仍处于矩形对象选框，不能保证孔洞点透或所有光效都有小框。柔光可能需要比实体更大的范围。玻璃切图内部可保留原场景折射颜色，移动到新背景不会物理自适应。

## 数据与文字

原生图表保存数值与工作簿快照，可读/改数据。显式的艺术标签是独立图片，PowerPoint 不会跟随图表自动更新。源工程检查单源数据和艺术绑定，发现过期标签时要求局部替换；不声称自动重新生成字体或验证 OCR 的所有正确性。

当前原生字段使用 Artifact Tool 的公开 API。特殊图表、动画、内部跳转链接、可编辑路径文字、复杂原生艺术效果需在具体任务中确认 API 和实测；本版没有提供这些已验证的通用封装。视觉导航不等于超链接。

`text_styles`提供源工程的角色样式复用，编译时生成每个对象完整style；它不是PowerPoint主题的双向绑定。纯色背景使用公开母版fill，PNG背景路径继续保留。渐变、描边、阴影、WordArt、字距和基线分别记录写入、导入、渲染、编辑、重开与目标应用状态，不能共享一个supported=true。

## 视频与媒体

视频必须保持真实媒体对象、文件或链接关系、位置比例及播放行为。poster只作封面，不能代替媒体交付。当前JS在官方AVI和H.264 MP4样例往返中均丢失真实媒体；已有PPTX在导入前先执行[音视频预检](media-preflight.md)，发现媒体或无法判定时停止这条往返路线，保留原件。

本次供应soffice headless入口可以渲染及重保存诊断稿，但所测H.264媒体保留同样失败；不存在由此自动获准的保媒体备用路线。源文件、后端版本、hash及失败范围集中在上述参考。PowerPoint/WPS及真实播放为NOT_RUN，不把命令行转换当实机播放，也不推断PPTX格式不支持视频。

按实际可用工具、权限和经验证能力调查后端：先核所选实现的API、格式/编码与最小媒体样例，再验证原媒体字节、关系、框和真实目标应用播放。允许且可用的PowerPoint自动化、PptxGenJS或受控OOXML实现可单独验证，不从格式文档推定实现成功。选定后端没有可靠入口时保护原件，记录版本和具体卡点，继续不依赖视频的工作。

## 验证层次

1. 结构：ZIP/OOXML、实际对象、图表数据、表格与工作簿关系
2. 渲染：从真正输出 PPTX 重新导入并逐页渲染，检查母图与重组效果
3. 工具编辑：实际导入、修改对象、另存再开诊断副本
4. 目标应用：实际 PowerPoint 或 Google Slides 的操作、保存和重开

前三层不能替代第四层。G05 试跑在工具里验证图片移动、文字输入、表格修改、图表值变更和重开，没有 PowerPoint/Google Slides 实机检查，也没有真实鼠标点击选区测试。当前回放延续同样证据边界。

Artifact Tool 导入后再导出诊断副本可能省略图表的工作簿。诊断用来观察编辑结果，不直接作为交付；正式构建从完整数据重新生成，并经 finalizer materializeLiteralChartWorkbooks 保留新图表值快照。这不保留外部原始工作簿的公式或血缘，不能用来偷换用户要求保留的原工作簿。

只有既有PPTX而要求原工作簿保持时，不能直接用新快照代替缺失依赖。已实测的有界恢复路线及停止条件见[原依赖保全案例](roundtrip-preservation-case.md)：先确认当前作者/修复规范，再让Artifact Tool完成文字编辑，仅恢复已唯一对应的原依赖。rc.3的独立CLI仅接受同路径、唯一owner的单barChart和五部件inline静态xlsx；一般Excel工作簿、其他图表或多图表不在此范围。它不修改宿主导出库，不能承诺任意PPTX无损编辑。

## 已验证教训的用法

第一次被拒绝的路线以代码排版为主、只用两张装饰图，缺少图片模型整页设计。后来的局部艺术字替换与紧裁解决了操作问题，却仍保留小字加下划线导航，用户再次否决。成功路线先让图片模型设计信息密集整页，将章节索引、标题、固定文案和艺术数值形成同一层级，然后保真拆层重组。

这说明必须在完整页面层面判断艺术设计，不是规定未来每套作品都用左侧索引、玻璃环、玫瑰色或六页。低噪提示降低随机颗粒是要求，不是已量化的成功率。用户认可 G05 的设计/编辑方式，内容与文案仍需 consumer 指导持续改进。
