# 恢复、故障和交接

恢复、局部修改和回放也先满足[全局图像工具前置](dependencies-and-start.md#必需的图像工具)。保留已完成文件与查清缺项不等于继续运行Skill；无可用生图工具时不自动转入纯改字或已有素材组装路线。

## 根据原因选择动作

| 现象 | 检查 | 下一步 |
|---|---|---|
| 没有可用图片工具 | 当前宿主真实生成/参考图编辑接口、权限及返回保存能力 | 停止整个Skill并说明缺项；已有素材、纯改字和代码组装不作为自动豁免，不声称已生成或已按完整流程交付 |
| 返回展示板/图层面板 | DRAW 是否混入工程说明；引用是否正确 | 简化当前视觉任务，使用真实母图；不把展示板切开当生产素材 |
| 黑/白底被误称透明 | probe 的 mode/alpha，工具透明参数 | 检查调用、授权的背景移除或重生；不要随手全局去弱 Alpha |
| 两次重复基本错误 | 工具真实 schema、附件、指令透传 | 停止同样盲试，换有依据的调用方式；不可借换 layer ID 刷预算 |
| 偏位/偏大但内容正确 | 目标框、实际源框、比例和遮挡 | 改 crop/destination，重建，不默认重生 |
| 玻璃/雾边消失 | 是否阈值删 Alpha、混合/透明度是否错误 | 恢复原料，检查设置和边缘，不用实体框规则卡材质 |
| 玻璃外透明但内部仍带旧背景 | Alpha 分布、不同底色叠放、源图内折射 | 说明 cutout 与真实透射区别；仅在用户编辑目标需要时做针对性修复，不承诺物理重建 |
| 艺术字多出其他对象的材质 | 是否用了 typography 模板，owns 是否只描述字本身 | 使用独立艺术字任务，保留字形与其原材质；不重做整张母版 |
| 隐藏主体仍有残影 | 背景是否真的补全 | 只修背景；不改所有已可用层 |
| 移动主体带走别层文字 | owns/excludes/copy_ids 是否清楚 | 只重生/编辑责任素材，保留其他层 |
| 原生字缺字/字体变样 | 字体文件、名称、覆盖、样式与真实渲染 | 使用有权限的真实字体；样本失败且无可靠修正依据时，按已定取舍转独立图片，不反复盲换字体名。未放宽的可改字承诺不能偷偷降级 |
| 原生字准确但行宽/字重偏离 | family/PostScript、字宽家族、字号、tracking、baseline | 先选近似字宽/字重，用 measure_text 辅助；重新看整图，不仅匹配行宽数字 |
| 显隐展示与文件似乎不对应 | report 中层名/文件、叶层或组、路径/版本/哈希 | 新目录重导出并逐张查看；未复现前不宣布代码 bug，不修改渲染逻辑碰运气 |
| PSD 缓存好看而重绘错误 | 实际层序、blend/opacity、缓存是否旧 | 修包装配置/代码并双解析，不能拿缓存图当源文件证明 |
| 脚本错误 | 真实路径、字段、源码尺寸、字体、输出碰撞 | 修具体技术错误；用新构建目录，别绕过检查声称成功 |
| Adobe/服务权限拒绝 | 返回的受限动作和目标 | 停该动作并报告；若必需图像工具因此不可用，整个Skill暂停。其他独立工作仅在前置仍成立且已获授权时继续，不绕过拒绝 |
| 文件保存结果不确定 | 已返回 ID/状态/版本 | 先查实际结果，不盲目反复上传新副本 |

## 暂停、重选与回退

### 接手前先确定真实现状

先读 START_HERE 或 resume 指向的当前构建、内容资源、素材来源和未完任务，再核对文件是否存在、最近修改时间、已有工具回执与保存 ID。活动列表缺失、一次轮询没有输出或旧进程不可见，都不能单独证明上次执行已失败；未知图片结果不重发，未知上传先查回执。

同一工程仍出现无法归属的写入时，暂停该工程的修改和发布，先与原执行者或协调者核对写入责任。可以继续只读审查及独立工作；新建副本不代表旧执行已经停止，不自动合并不明修改。确认当前由谁登记、改配置和发布之后再继续，避免多位 AI 同时覆盖一个 plan、deck、数据源或版本记录。

接手者应能从源包找到以下实际信息，无须旧聊天补答案：当前格式与构建；准确文字和数据的唯一来源；标题的来源及可改范围；指定媒体的原件、使用限制与对应对象；选中母图和素材；字体及后端依赖；未完调用的真实状态；已授权的下一动作。缺项先从包中已有文件核实，真正影响继续工作的缺口再问，不因为交接模板某一栏没填就阻断整个任务。

已有 brief 之后又获准改日期、报价等事实时，保留原材料，并把新决定及其优先关系写入当前内容入口。修改渲染源后也核对讲者注释、另一格式、内容契约和未使用的默认值；历史母图与旧版继续标为历史，不当作当前事实重新套回。能共用同一字段就绑定；存在必要副本时明确用途并逐项核对，不能只改画面中最显眼的一处。

局部修改前，沿当前工程的引用查清“改哪一处→哪些对象读取→哪里派生显示”。两个格式使用同一日期时引用同一字段；报价数值与“2,100元含税”等显示文案按本项目明确的币种、单位、分组和税务表达派生，不能要求数值与显示字符串直接相等。复用已有内容准备脚本和data_bindings即可，不必另建模板协议。派生文案、数字清单与构建配置放新版本输出，标明生成来源；历史brief和母图保持历史身份。

实际运行准备与编译后，检查输出所引用的数据文件和目标对象值。data_bindings会覆盖目标路径的字面值，因此仅改config中的旧价可能不生效；金额也可能已更新而另一格式日期仍读取旧副本。用一次只改权威字段的真实重建检查两格式及对应内容记录，再按下文核未改范围。没有自动引用的旧工程继续逐项核对，不把“任意改一处都能同步”写成已有能力。

`project.py snapshot` 保存 plan/receipts。record 会自动保存之前指针。`restore` 只能使用该项目 revisions 下的快照；恢复前再快照，原图片不删。构建目录 B01/B02 保留，便于比较选择。不要把工程回退理解为删除失败证据。

旧素材恢复用 conversation_history 与真实原调用/上传来源；没有 Prompt 或 ID 就写不可见。主图更换后检查现有层是否仍合适；不自动无条件重生，也不盲信旧配置。重选原候选是历史导入，不是一次新模型调用。

当前工具要求生图后结束回合时，先保存 plan/job；后续有真实结果再 record。不得暗示宿主实际上没有持续执行的后台流程仍在运行。

## 何时问用户

- 默认母版/方向与图层架构两个关键节点（可合并），或用户另定的阶段点；明确全自动授权则记录自主选择继续
- 缺不可推断的准确文字、品牌资产或冲突的编辑要求
- 必须超出现有工具能力、外部费用或权限时，需要真实选择/授权
- 两次有变化的修复仍达不到关键要求，需要额外时间或降级取舍

架构确认后减少未被放宽的可编辑能力、合并用户指定独立层、改换母版方向等，按interaction-and-layers.md重新确认。已明确美观优先并接受部分图片文字的取舍直接执行，不重复问；小幅注册、正常工具检查、局部修已有素材也不新增确认。自主执行与用户看图批准分开记录。

## 交付的三种状态

final：执行者已完成需求并实际看图；不自动表示用户批准。review：用户要求的审阅尚未完成，明确待决定事项。diagnostic：未形成合格目标格式成品的诊断材料，必须标为诊断，不假称完成源文件。

使用 [双格式交接模板](../resources/handover.md) 写 START_HERE。PSD 工程包含当前 PSD/PNG、plan/manifest；PPTX 工程包含当前 PPTX/预览、deck、content/data 及设计资源。两者都带齐选中素材、母图、来源、必要代码与依赖说明和校验哈希；不默认把失败展示板送给下一位图片模型，也不夹带字体、账号、密钥、依赖缓存。需要失败取证时单独注明并提供有关文件。

源包解压后配置的相对路径必须仍能找到资源。记录本项目实际使用的命令和入口，不仅写“运行 assemble”；字体文件需接收者合法准备，PPTX 的当前 Presentations 运行时按其 Skill 设置。在全局工具前置已满足时，已有素材重建可以不发生新图片调用；两者不能混为一谈。包不内置运行时，不能称为免安装软件。

局部修改复验同时检查改动目标和未改内容。对原媒体比较嵌入字节，对 PSD 比较其他图层，对 PPTX 核对对象、关系目标、图表及工作簿内容，再看实际渲染。重建可能重新生成 creationId、关系 ID 或 ZIP 时间；发现差异先定位，只有证实这些元数据变化后才按解析后的关系和内部部件比较，不笼统忽略全部 XML 差异。源配置重建、真实文件改字后保存重开、目标应用编辑分别记录。

检验接手能力时，让没有旧聊天的执行者仅凭 Skill 包、本次 brief 和必要原文件开始，再让另一位仅凭产出的源工程完成一次具体修改。分别观察能否找到入口、作出内容/视觉选择、产生真实成品、修改目标对象并保住其他内容；技术单测只验证工具，不能代替这项任务。若复用了旧上下文、作者提示了答案或只有同一执行者复验，应准确说明范围，不称独立首轮通过。

附件投递失败不等于文件损坏。先保存实际错误、文件大小与已返回 ID，不猜测固定上传阈值；优先交付可接受的 PSD/预览和 deliver_project 的紧凑 source 包，较大的完整取证包保留。保存成功与消息附件投递成功分别记录，不因一次批量失败反复上传所有文件。
